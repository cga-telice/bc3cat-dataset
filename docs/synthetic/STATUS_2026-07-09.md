# BC3CAT-Syn — Status Report

**Date:** 2026-07-09  ·  **Branch:** `synthetic`  ·  **Author:** César

## What this project is doing

We're building a *stressed* version of the BC3CAT construction-catalog dataset for evaluating
retrieval systems. The original dataset is too easy for lexical retrievers because both the
search query and the search result come from the same generation rules (~97 % accuracy with
simple word-matching). BC3CAT-Syn rewrites the catalog text in controlled ways — synonyms,
paraphrases, unit conversions, template restructurings — that preserve the meaning but change
the wording, so retrieval methods actually get tested.

## What's built

The full generation pipeline is done and tested (1 018 automated tests passing). Highlights:

- **Rule-modification engine** — 13 distinct rewrite types across four layers of the catalog
  (parameter values, text-variable fragments, templates, and newly added parameters).
- **LLM proposer** — asks a local `phi4:latest` model (via Ollama, free) for candidate
  rewrites in Spanish; every response is recorded to disk so re-runs are offline and free.
- **Menu-first review workflow (new — Sprints 37–38)** — this replaces the earlier
  "generate everything, then sample-review the output" approach. The pipeline now:
  1. Deduplicates rewrite targets across the catalog (an axis value like *"Diurno"* is
     reviewed **once** even though it appears in 20 concepts — 83 % effort saving).
  2. Asks the LLM for **10 alternative rewrites** per unique target.
  3. Produces two files per rewrite type: a machine-readable JSONL for downstream code and
     a **Markdown file with clickable checkboxes** for the human review.
  4. After the review, a parser translates the ticked boxes into approved rewrites and
     the sampler will draw the final corpus from those.

## Progress: live generation completed

Yesterday afternoon we ran the full menu build against `phi4:latest` on 25 concepts of the
OBRA CIVIL chapter (OEB subset). 92 min of local GPU time, no cloud cost, 636 model calls,
**2 918 candidate rewrites produced across 11 populated rewrite types**. All artefacts are
committed to the branch under `docs/synthetic/menus/` (11 review files) and
`data/synthetic/menus/` (matching JSONL files).

Quality signals from the mechanical scorecard (Spanish fluency is César's manual judgement,
not yet complete):
- L2 rewrites (paraphrase / expansion / compression) generated 100 % — no schema failures.
- `new_param` (adding a new axis) generated 100 %.
- `synonym_label` at 88 %, `omission` at 53 % — the omission validator correctly rejects
  outputs where the wrong placeholder was dropped.
- Dedup working as designed: `BANDA DE MANTENIMIENTO / i >= 5 horas` is reviewed once for
  21 concepts instead of 21 times.

## Problems encountered

Two real-data bugs surfaced on the first live run and were fixed the same day:
1. **Real catalog data mixes three text-variable shapes** (string, list-plain, list-conditional).
   The pipeline was applying the shape adapter in one place but not the other, so real data
   crashed. Fixed by applying the adapter consistently at pipeline entry.
2. **60-second LLM timeout was too short** for heavy prompts asking for 10 alternatives at
   once. Bumped to 5 minutes; also added a *resuming cache* wrapper so a crashed run picks
   up where it left off instead of re-hitting the model. The 264 responses already recorded
   before the timeout resumed automatically.

Both fixes have regression tests so they can't silently return.

## What we're deliberately *not* doing

- No cloud LLM cost — everything runs locally via Ollama.
- No merging back to `main` — BC3CAT-Syn is a permanent parallel branch by design.
- No manual review of rendered items across concepts — the menu-first approach reviews
  the *rewrites* once, then samples the corpus deterministically. Much cheaper than
  reviewing hundreds of thousands of rendered lines.
